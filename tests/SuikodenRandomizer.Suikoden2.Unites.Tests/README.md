# Linked S2 unite tests

This fixture links the actual production `Gsd2UniteRecipes.cs`, `Gsd2Unites.cs`, `Gsd2ShuffledUnites.cs` and `Gsd2UniteRawResources.cs`, plus the S2 Core project. `expected-native.json` is independently parsed from the shipped original `UNITE_DATAS` Unity asset. It covers all 51 slots, every scalar and ordered participant byte, the twelve high-bit status exemptions, native-derived correction/status fields, immutable data, variants and special recipe metadata.

The full matrix verifies native derived fields on first use and across Reset/new-battle reuse of the same loaded table. It includes all 50 recipes across six foreign-role formations (300 flows), each participant as initiator (121 further flows), one- and two-action actors, native upgrade 3 to 40, protected Riou/special IDs, multiple linked groups, rejected native state and queue mutations, temporary ID rollback failures, execution ownership, helper nesting and async resource scopes. Each primary formation flow models both a waiting playback frame and a completing frame, checking PM and graphics donor identities inside the frame and exact canonical restoration afterward.

The iterator owner fixture is bound to an independently read PE PropertyDefinition: `__4__this`, token `1700c2af`, in installed GSD2 SHA `8a63846c…`. `expected-iterator-property.json` retains the complete selected property rows. Accessor text is not used to infer property names. The production resolver runs against independent CLR shapes covering the former three-underscore typo, static/indexed/inherited/wrong/ambiguous properties and invalid/ambiguous `MoveNext` signatures. These shapes are generated managed test types; they do not load game code. A separate metadata-only suite applies the same resolver to the real installed interop assembly.

`FakeGsd2` supplies managed shapes using the verified real interop property types. Explicit `NativeModel` helpers simulate the reviewed canonical participant matching, native action-count increment, action-record linking, target propagation, donor identity lookups and helper equipment access. An explicit AoE/status/reaction example tests observation of controlled model results; it is not a native damage formula. The fake Harmony registry permits the production code to inspect the exact installed-prefix contract, without installing any detour. Runtime mapping is a controlled active-party model. The graphics/presentation classes here are callback holders; this fixture tests the controller's policy lifetime, while separate fixtures test their real source integrations.

No game assembly is loaded or executed. Native formulas, RNG probabilities, animations, sounds, camera behavior, real coroutine execution, actual asset resolution, real Harmony installation and gameplay remain outside this managed fixture. `verification.json` records the precise linked production and fixture source hashes, assembly hashes and build/test logs. A passing managed calculation/playback model must not be represented as a native gameplay pass.
