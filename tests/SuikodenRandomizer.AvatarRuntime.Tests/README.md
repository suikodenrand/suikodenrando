# Managed runtime adapter checks

This project links the **actual production `AvatarRuntime.cs`, its fixed-roster, Nuzlocke and diagnostic partials, and `StartingGearBalancer`/`StartingGearBalancePolicy`** and uses real Core shuffle profiles, campaign state, strict binding codec and batch transaction orchestration. It executes the adapter against deliberately small managed native test doubles in the separate `AvatarRuntime.TestDoubles` project. `AvatarNativeData`, item-table rows, logging, paths, scene access and binding storage are test doubles.

The checks cover transient startup readiness, exact live-base binding, complete pristine donor snapshot use, excluded identities, no repeated initialization, saved-seed restore, progression-preserving replay, full rollback, title lifecycle and identity rejection.

Existing checks use Original starting gear. Balanced-gear checks execute the actual production balancer and policy against a controlled item catalog: opening and later recruitment tiers, compatible armor, worn and spare armor, weapon sharpening, preserved weapon identity/runes/stats/items, one-time fixed templates, Nuzlocke replacement inheritance, and all-mode reloads with the opposite current preference. Nuzlocke's saved preference also governs later roles.

Nuzlocke checks exercise seeded startup, latched companion knockouts even after revival, unique permanent retirement across forced and returning story roles, inherited progression and loadout, battle save refusal, wipe/retry consumption, save/load without initialization, and transactional native rollback. Tir always retains his native asset and base, including when IncludeTir is forced on, after a knockout, and across scene reconstruction. A complete 75-companion run consumes fresh reserves and living inactive survivors while leaving Tir available for solo play and saving; a subsequent full wipe cannot request another reserve retry. The battle doubles model the native one-based battle arrays. Native defeat routing and encounter reconstruction still require an in-game check.

Diagnostic checks verify that post-KO evidence associates canonical roles with the actual donor, resident and base pointers, includes the current transition location and party count, and leaves native progression, pointers and roster layout untouched. They also exercise native-world teardown and repeated frame observation without duplicate world-change records. The journal is a recording test double here; crash capture, file flushing and rotation are verified separately.

The native shared-resource retry adapter is excluded from this runtime harness, and its reset entry point is a no-op test double. `SuikodenRandomizer.NuzlockeRetry.Tests` links the actual production retry resource gate to test asynchronous loading, readiness, cancellation and timeout. Native OPD loading and encounter reconstruction still need the genuine-reference build and in-game testing.

Passing this suite does **not** compile the complete plugin against real BepInEx/Unity/Il2Cpp references, install or execute native hooks, validate native object ownership or establish gameplay compatibility. The real GSD1 metadata gate and installed-reference plugin build remain separate requirements.
