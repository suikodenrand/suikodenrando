# Building Stars of Destiny 0.14.6

This guide builds randomizer **0.14.6** and launcher **1.0.7**. The matching source is tagged [v0.14.6](https://github.com/suikodenrand/suikodenrando/tree/v0.14.6).

Build on Windows x64 from a clean checkout. This repository contains the project source; it does not supply the game, generated game interop assemblies or a personal save. Building does not require changing files in the game installation.

## Prerequisites

| Requirement | Version or purpose |
| --- | --- |
| .NET SDK | **10.0.403**, pinned by `global.json` |
| Game | Your own Steam Windows copy of Suikoden I & II HD Remaster, app `1932640` |
| BepInEx | **6.0.0-be.697+5362580**, **Unity IL2CPP Windows x64** |
| Local interop | Both `BepInEx/interop/GSD1.dll` and `GSD2.dll`, plus the other assemblies generated by BepInEx |
| Python | 3.12 or newer for release-archive packaging |
| NSIS | 3.11 for the full setup EXE; not required to compile plugins or make the manual ZIP |

Install the [official BepInEx build](https://builds.bepinex.dev/projects/bepinex_be/697/BepInEx-Unity.IL2CPP-win-x64-6.0.0-be.697%2B5362580.zip) in the supported game folder. Run the game once to let it obtain Unity reference files and generate interop assemblies, then close the game and launcher. Follow the [official IL2CPP installation guide](https://docs.bepinex.dev/master/articles/user_guide/installation/unity_il2cpp.html). Do not use the Mono, x86 or BepInEx 5 distribution.

The tested BepInEx archive's SHA-256 is:

```text
616ec7eb06cf11b2a0000e8fcef04d1b12bb58e84a2e0bdac9523234fc193ceb
```

The supported original `GameAssembly.dll` SHA-256 is:

```text
e093f175eaf3734d293ca0a236c652dd7fcc72ea5fa10d7b21103edf12f11c3a
```

This is a compatibility pin, not a game download. Do not obtain proprietary assemblies from another user's repository. Generate references from your own installation and keep `BepInEx/core`, its private loader runtime and interop output together. The native-facing projects read these references through `GamePath` or `BepInExPath`; they do not copy them into the plugin output.

NuGet access is needed when the SDK's reference packs, runtime packs or project restore inputs are not already cached. The game-facing host and ATB target .NET 6, shared libraries target .NET Standard 2.1, and the standalone Windows launcher targets .NET 10. A .NET 10 SDK can build these targets after restoring their reference packs.

## Build the binaries

From the repository root, set your local game path in PowerShell:

```powershell
$game = 'D:\SteamLibrary\steamapps\common\Suikoden I and II HD Remaster'
dotnet --version
dotnet build src/SuikodenRandomizer.Unified/SuikodenRandomizer.Unified.csproj -c Release "-p:GamePath=$game" -p:Version=0.14.6
dotnet build src/SuikodenRandomizer.S1BattlePreview/SuikodenRandomizer.S1BattlePreview.csproj -c Release "-p:GamePath=$game"
$atbSha256 = (Get-FileHash src/SuikodenRandomizer.S1BattlePreview/bin/Release/net6.0/SuikodenRandomizer.S1BattlePreview.dll -Algorithm SHA256).Hash.ToLowerInvariant()
dotnet publish src/StarsOfDestiny.Launcher/StarsOfDestiny.Launcher.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:RuntimeFrameworkVersion=10.0.14 "-p:ReviewedAtbSha256=$atbSha256" -o artifacts/0.14.6/launcher
```

Apply the global `Version=0.14.6` property to the **unified runtime build only**, matching the production build's version metadata for all four runtime payload DLLs. Build the separate ATB component without that override so it retains **0.15.2**. Publish the launcher separately with its project product version **1.0.7**. Do not carry the unified build's version override into those separate commands.

The combined runtime payload consists of these four files from `src/SuikodenRandomizer.Unified/bin/Release`:

```text
SuikodenRandomizer.dll
SuikodenRandomizer.Core.dll
SuikodenRandomizer.Suikoden2.Core.dll
SuikodenRandomizer.Shared.dll
```

ATB builds to `src/SuikodenRandomizer.S1BattlePreview/bin/Release/net6.0/SuikodenRandomizer.S1BattlePreview.dll`. It is a separate optional component. Keep the complete launcher publish folder together, including its private .NET 10 runtime and notices. The game's separate BepInEx `dotnet` folder is not interchangeable with that launcher runtime.

The launcher publish target also copies the original core runtime license, core third-party notices and Windows Desktop runtime license into the publish folder. Packaging checks that all three notice files are present.

### Rebuilding optional ATB

The launcher deliberately checks the reviewed ATB binary's SHA-256 before copying it into the plugins tree. A locally rebuilt DLL can have a different hash because build paths and debug metadata can differ, even when its source behavior is unchanged. A clean compile alone does not qualify a new ATB binary for activation.

When producing a custom reviewed ATB build, review/test that binary and pass its hash as `ReviewedAtbSha256` when publishing the matching launcher, as shown above. The build records a validated 64-digit hash in assembly metadata; the launcher continues to require an exact reviewed-binary match. `Build-Release.ps1` computes and passes this property automatically. Without the property, the launcher retains the original reviewed 0.15.2 hash as its default.

Preserve the validation guard; do not turn it into unconditional acceptance of arbitrary DLLs. Keep the reviewed binary and the matching launcher together in a custom package. The published 0.14.3 assets retain the reviewed ATB hash recorded by their manifests.

```powershell
Get-FileHash src/SuikodenRandomizer.S1BattlePreview/bin/Release/net6.0/SuikodenRandomizer.S1BattlePreview.dll -Algorithm SHA256
```

## Run checks

Run the managed check from a checkout with Git, PowerShell 7, the pinned SDK and Python 3.12 or newer. GitHub Actions runs the same command.

```powershell
pwsh -File eng/Check-Quality.ps1
```

This verifies whitespace in new and edited C# files, builds the launcher and CTB editor with the shared .NET analyzer policy, runs the managed test executables and runs the Python packaging tests. These checks use repository fixtures and run on Windows without game files. The formatting check compares the working tree to `HEAD` by default. For committed changes, pass the intended comparison commit with `-BaseRef`, for example `pwsh -File eng/Check-Quality.ps1 -BaseRef origin/main`. Use `-FormatOnly` to check formatting by itself.

The specialist tests for native signatures, real dialogue data or built release DLLs have separate inputs. Use the commands below and the individual test instructions when working on those boundaries. Native gameplay verification uses your own installation.

Most tests are small executable projects. Run the relevant projects with `dotnet run`, rather than assuming a solution-wide `dotnet test` command will find them. These examples use managed fixtures rather than launching the actual game:

```powershell
dotnet run --project tests/SuikodenRandomizer.AvatarRuntime.Tests/SuikodenRandomizer.AvatarRuntime.Tests.csproj -c Release
dotnet run --project tests/SuikodenRandomizer.Suikoden2.Runtime.Tests/SuikodenRandomizer.Suikoden2.Runtime.Tests.csproj -c Release
dotnet run --project tests/StarsOfDestiny.Launcher.Tests/StarsOfDestiny.Launcher.Tests.csproj -c Release
dotnet run --project tests/StarsOfDestiny.Launcher.Ui.Tests/StarsOfDestiny.Launcher.Ui.Tests.csproj -c Release
```

The UI checks require a Windows desktop environment. The compiled-host metadata checks take the built unified DLL and an output report path:

```powershell
dotnet run --project tests/SuikodenRandomizer.Unified.Metadata.Tests/SuikodenRandomizer.Unified.Metadata.Tests.csproj -c Release -- src/SuikodenRandomizer.Unified/bin/Release/SuikodenRandomizer.dll artifacts/0.14.6/metadata-checks.json
```

After rebuilding ATB, the launcher pairing test verifies the build-property hash guard against that actual DLL:

```powershell
dotnet run --project tests/StarsOfDestiny.Launcher.AtbBuild.Tests/StarsOfDestiny.Launcher.AtbBuild.Tests.csproj -c Release "-p:ReviewedAtbSha256=$atbSha256" -- src/SuikodenRandomizer.S1BattlePreview/bin/Release/net6.0/SuikodenRandomizer.S1BattlePreview.dll
```

Create the report's parent directory if it is absent. Some specialist test projects have their own README or arguments; consult them before running. Managed tests and metadata checks do not prove that every native battle, story script or campaign is correct. Record in-game checks separately and state what remains untested.

### Joining inventory/equipment validation

`Shuffle/JoiningEquipment=MatchRole` is the fresh default in both game CFGs. It uses the original role's full starting inventory at the replacement's first party join, including consumables and equipped gear. Incompatible armor/accessories use comparable wearable equipment. `Donor` preserves replacement starting-inventory behavior. The policy applies to Shuffle, FixedChosen and FixedRandom and is separate from `JoiningWeaponLevel`. A saved campaign keeps its inventory policy and first-join history; campaigns predating this metadata retain Donor behavior without a retrofit.

Run both runtime fixture projects and both launcher projects listed above. The launcher cases check independent per-game choices across all three modes, presets/advanced-editor round trips, config backups, missing legacy keys and the 0.14.4 host requirement. Check package metadata/defaults without producing packages:

```powershell
python -m unittest discover -s packaging/release/tests -v
```

The 0.14.6 checks cover S1 save admission and fixed rosters, S2 recruitment, save binding collisions and graphics, launcher settings and installer recovery. Record native playtesting separately. Historical evidence for the joining equipment feature is in the [0.14.4 notes](docs/release-0.14.4.md).

For broader native coverage, record these checks separately in each game:

1. Start a disposable new campaign with MatchRole. Compare the original role's starting inventory with its replacement's first join, including consumable counts and equipped state.
2. Exercise a replacement that cannot wear the original armor or accessory. Confirm a comparable legal substitute can remain equipped and is accepted by the native equipment menu; confirm the replacement's own weapon and runes remain intact.
3. Change equipment, consume an item, save and reload, then leave/rejoin where the story permits. Confirm no item duplication, restored consumables or equipment reset. Check that changing launcher policy does not rewrite this saved campaign.
4. Repeat representative joins in Shuffle, FixedChosen and FixedRandom, then test Donor. Load a backed-up pre-0.14.4 campaign and verify its inventory stays unchanged under the legacy policy.
5. Exercise the normal opening and quick start. Keep saves and all matching campaign sidecars paired; do not remove bindings to force a policy change.

The remaining checklist requires live-game observations. Managed tests and catalog/native static analysis cannot establish that every recruitment script is correct.

## Build release packages

`packaging/Build-Release.ps1` orchestrates the source build and packaging without installing into the live game. Its default mode builds binaries. Use `Manual` for the mod-only ZIP or `All` for both that ZIP and the full setup:

```powershell
.\packaging\Build-Release.ps1 -GamePath $game -PackageMode Binaries
.\packaging\Build-Release.ps1 -GamePath $game -PackageMode Manual -DownloadDependencies -OutputDirectory artifacts/0.14.6-manual
.\packaging\Build-Release.ps1 -GamePath $game -PackageMode All -DownloadDependencies -MakeNsis 'C:\Tools\NSIS\makensis.exe' -OutputDirectory artifacts/0.14.6-full
```

The default output root is `artifacts/0.14.6`, with `runtime`, `atb`, `launcher`, `packages` and `dependencies` subfolders. Use `-Dotnet` to select an SDK executable, `-Python` to select Python, `-OutputDirectory` to change the output root, or `-DependenciesDirectory` to use another dependency cache. Use a fresh package output directory for each packaging run; the packager refuses to overwrite an existing staged package or target a game installation.

`-DownloadDependencies` explicitly permits fetching the pinned upstream inputs. Without it, the required dependency files must already be in the cache with matching hashes. The manual package needs the pinned Suikoden Fix archive. The full setup also needs the pinned BepInEx archive and three corresponding source archives; it distributes their verified extracted source folders, not nested ZIP files. Packaging pins are recorded in `packaging/release/dependencies.json`. Do not substitute a current bleeding-edge loader and label it the tested 0.14.6 bundle.

`-StageOnly` can validate and assemble the full setup's payload without compiling its NSIS EXE. It does not constitute qualification of a finished installer.

For already built binaries, the Python packager can also be invoked directly. This example downloads missing pinned inputs into an ignored cache and creates a manual ZIP in a fresh output directory:

```powershell
python packaging/release/build.py --mode manual --runtime-dir src/SuikodenRandomizer.Unified/bin/Release --atb-dll src/SuikodenRandomizer.S1BattlePreview/bin/Release/net6.0/SuikodenRandomizer.S1BattlePreview.dll --launcher-dir artifacts/0.14.6/launcher --dependencies .cache/release-dependencies --output artifacts/manual-package-0.14.6 --download-dependencies --reviewed-atb-sha256 $atbSha256
```

Use `--mode setup --makensis <path-to-makensis.exe>` for just the full setup or `--mode all` for setup and the manual ZIP. `--stage-only` skips NSIS compilation. Pass the same reviewed ATB hash used when publishing the matching launcher.

## Produce the public downloads

For Windows setup revision **0.14.6-r3**, use the verified gameplay plugin, battle preview and launcher files from the 0.14.6-r2 setup. Set `$original` to the verified runtime and battle preview staging folder, `$publish` to the complete launcher folder from that package, and `$dependencies`, `$nsis` and `$output` to the dependency cache, NSIS compiler and an empty output folder. [0.14.6 release files and checksums](https://github.com/suikodenrand/suikodenrando/releases/tag/v0.14.6)

```powershell
$runtimeCommit = git rev-parse v0.14.6
$launcherCommit = git rev-parse package-v0.14.6-r2
$publicAtb = Join-Path $original 'atb/SuikodenRandomizer.S1BattlePreview.dll'
$hash = (Get-FileHash -Algorithm SHA256 $publicAtb).Hash.ToLowerInvariant()
python packaging/release/build.py --mode setup --package-revision r3 --runtime-dir (Join-Path $original 'runtime') --atb-dll $publicAtb --reviewed-atb-sha256 $hash --launcher-dir $publish --dependencies $dependencies --makensis $nsis --runtime-source-commit $runtimeCommit --launcher-source-commit $launcherCommit --output $output
```

Run install, repair and both uninstall choices in disposable game folders before publishing. The earlier revision 2 source documents the manual ZIP, standalone launcher and CTB preview.
