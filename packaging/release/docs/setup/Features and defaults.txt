STARS OF DESTINY 0.14.4 - FEATURES AND DEFAULTS

COMPONENTS
Combined randomizer       0.14.4
Windows launcher          1.0.5, self-contained Windows x64
Suikoden I ATB Preview    0.10.1, optional and installed disabled
Suikoden Fix              upstream release 1.5.2b (plugin reports 1.5.2)
BepInEx                   6.0.0-be.697, Unity IL2CPP Windows x64
Loader .NET runtime      6.0.7, private to the game loader
Launcher .NET runtime    10.0.14, private Windows Desktop runtime

BOTH GAMES
Seeded character-role shuffle; five chosen companions; seeded random fixed
roster; optional protagonist shuffle; each game's quick start; separate
campaign mappings and settings; one combined host and shared F6 interface.
Recruitment requirements and story roles remain native. Names, portraits,
party and combat appearances follow replacement characters. Some custom
scene animations retain native handling. Saved campaigns retain their own
seed and mapping even if the launcher is changed to a different seed.

ENGLISH DIALOGUE
Supported dialogue mentions use shuffled character names. Native custom-name
tokens and event commands are preserved. This is a curated message system,
not a blanket substitution in every string. Ambiguous references, unsupported
messages and other languages retain the original text. Fresh default: on.

SHUFFLED UNITES
Native Unite eligibility follows the actual displayed fighters, including
characters occupying unrelated story roles. The implementation covers 32 S1
and 50 S2 recipe records, including alternate groups and native conditions;
those counts are recipe records, not distinct attack names. Native targeting,
animations, damage/effects and participant action use are retained. Both
games' shuffled Unite previews are enabled by the fresh package defaults.
They require normal turn-based battles. S1 ATB and the one-shot attack probe
are not supported with shuffled Unites. Broader in-game coverage is pending.

JOINING WEAPONS
S1 fresh default: TirVariance. Each eligible replacement's first joining
weapon level follows Tir's current weapon level with a seeded -3 to +3 offset,
including a possible exact match, clamped to the legal weapon-level range.
S1 also offers MatchRole and Level1.
S2 fresh default: RiouVariance. Each eligible replacement's first joining
weapon level follows Riou's current weapon level with the same seeded -3 to
+3 offset, including a possible exact match, clamped to the legal range.
S2 also offers MatchRole (the original story role's joining level) and Level1.
The replacement retains its own weapon identity. Adjustment happens once;
later rejoining and saved games retain earned sharpening. Policies are bound
to the campaign; changing the launcher does not downgrade old saves. Old
campaigns without policy metadata retain their previous behavior. Protected
story combat setups keep native handling; S2 natural weapons remain level 0.
These options do not alter character level, armor, growth or runes.
RiouVariance was introduced in 0.14.3. Managed tests cover the new policy; native
first-join playtesting of this option is pending. Existing campaign policies
are never silently replaced by the new default.

JOINING INVENTORY AND EQUIPMENT (NEW IN 0.14.4)
Fresh default for both games: Shuffle/JoiningEquipment=MatchRole. In the
launcher, choose Original role's starting inventory under Characters.
At the replacement's first party join, it receives the original story role's
full starting inventory, including consumables such as Medicine and equipped
items. Incompatible armor and accessories use comparable equipment the
replacement can wear. The replacement keeps its own weapon identity and
rune setup. Joining weapon-level choices remain separate.
This works in Shuffle, chosen companions and random fixed-roster modes.
Replacement's starting inventory (Donor) preserves the previous behavior.
The policy and first-join history are saved with the campaign. Acquired
items, consumption and equipment changes survive later joins and reloads.
Existing campaigns without this feature's saved metadata keep Donor behavior;
upgrading does not retrofit their inventory. Changing the launcher affects
new campaigns rather than rewriting saved inventory. Keep Save and all
BepInEx/config campaign sidecars together. An S1 native test checked Meg
replacing Viktor at first join and a subsequent native save. Reload was not
observed in that test. Broader S1/S2 join, compatibility and rejoin coverage
remains limited; managed tests cover saved-policy persistence.

QUICK STARTS
Fresh default for both games: Opening.
S1 BeforeViktor starts at the prepared Gregminster checkpoint before Viktor
joins. S2 ViktorCamp starts at the first camp interior, before the first
chores. These are new-campaign starts, not copies of a player's current save.

S1 TREASURE (EXPERIMENTAL)
132 ordinary item locations use a deterministic campaign-seeded reward map.
Potch, Blinking Mirror, recruitment-related Sound Orb, Window Orb and
Illustrated War Scroll, and the special Dwarves' Vault reward stay original.
Native item granting and open-state handling are retained. Launcher 1.0.5
has one checkbox: Enable chest shuffle for new campaigns. Existing saves
retain their stored policy. To change one, choose the checkbox value, Apply,
select its snapshot and reset its chest settings, then load that save.
The reset keeps a backup and preserves acquired items and opened chests.
On Apply, the launcher clears an older Treasure/Enabled=false global pause
so saved shuffles resume. Unticking the new-campaign checkbox does not pause
an existing shuffled policy. The original packaged CFG defaults remain
Treasure/Enabled=false and Treasure/ShuffleChests=false. The first launcher
Apply sets Enabled=true while ShuffleChests stays false unless selected;
new-campaign chest randomization therefore remains off by default.
Manual CFG editing can still pause with Enabled=false; a later launcher
Apply clears that pause. S2 chest shuffle is not implemented.

S1 ATB (OPTIONAL, EXPERIMENTAL)
Not selected in setup by default. Selecting the component installs the
separate plugin and, if absent, a disabled config. It does not enable ATB.
Heroes and enemies act when SPD meters fill. DEX modifies enemy charging and
can contribute to randomized opening charge. Individual native menus support
native targeting, Attack, Defend, Rune, Item, escape options and Auto. Ready
heroes can queue commands while other actions play. Meters reset and resume
charging after actions; fighters can act repeatedly. Queued Attacks can
retarget another enemy in range when their selected enemy dies. Enemy actions
do not discard the player's selected command. Native party/enemy lists stay
visible during targeting. Auto starts without its old confirmation.
Fresh ATB config: Enabled=false, OneShotAttack=false, ActiveAtb=true,
RepeatTurns=true, ReadyCommands=true, NativeReadyMenus=true,
NativeSpdMeters=true, ActiveInput=true, EnemyDexCharge=true, OpeningCharge=true.
Disable S1 shuffled Unites before enabling ATB. Scripted encounters and every
command combination need wider testing. S2 keeps native turn-based combat.

F6 AND LAUNCHER
F6 is hidden at launch by default; visible modes use text with no black box.
F6 cycles Full, Compact and Hidden for the current session. A configured
startup view is respected. Fault messages can still appear as text.
The Windows launcher manages per-game seeds, modes, companions, starts and
weapon and joining-inventory policies; settings tabs; JSON presets; config backups; saved chest
policies; optional ATB; and launching the game. Many display, audio and QoL
controls configure the included upstream Suikoden Fix plugin.

SUIKODEN FIX
Included unchanged with its notices. Fresh defaults use normal damage,
experience, money, loot and encounter rates. Save Anywhere and save-slot
settings retain upstream/default behavior. Existing Fix config is preserved.

INSTALLATION AND RESTORE
The full NSIS installer includes the required loader and separate private
runtimes. It verifies the supported game build and payload, backs up changed
files transactionally, and preserves existing configs, campaign bindings,
saves and unrelated plugins. It stops on unsupported/conflicting loader
files or duplicate plugin copies. An unchecked optional component is not an
instruction to remove an existing installation of that component.
Current-user Start Menu shortcuts open the launcher and support folder.
Restore.cmd reverses a selected installation transaction; there is no broad
uninstaller that deletes unrelated BepInEx files. First BepInEx launch still
needs Unity reference downloads. No compiler, SDK or package manager is
needed to install this bundle.

NOT INCLUDED
Personal saves, generated interop/cache files, custom music, the separate
Audio Redirector, Nuzlocke, S2 ATB/chest randomization, extra rune slots and a
shared-inventory or storage rewrite. See the project website and GitHub release for current downloads.
